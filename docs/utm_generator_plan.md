# План реализации — генератор UTM-меток + реестр + сокращатель (v2)

> Источник требований: «ТЗ — генератор UTM-меток и сокращатель ссылок (ЕГЭленд) v2».
> Апгрейд существующего инструмента (приложение `marks`), а не новый сервис.

## 1. Контекст и корректная модель системы

**«Автомаркс» = этот проект** (`automarks.tw1.ru`). Внешнего сокращателя нет.

Текущая цепочка: `Bot → Branch → Tag`. `Tag` несёт UTM и номер; ссылка на рекламу —
`telegram.me/<bot>?start=<номер>` (`Bot.build_tag_url`, [models.py:77](../marks/models.py)).
Человек кликает рекламу → входит в бота со стартовым номером → бот резолвит номер в UTM
через `bot_api` ([views.py:528](../marks/views.py)).

**Проблема v1:** UTM в `Tag` — свободные `CharField` ([models.py:433](../marks/models.py)),
заполняются руками и вразнобой. Нет справочника, валидации, реестра с автором/кликами/дедупом.

### Маппинг терминов ТЗ

| ТЗ | В проекте |
|---|---|
| «Автомаркс» / сокращатель | этот проект |
| «метка» | набор UTM + короткий код |
| «короткая ссылка» | короткий код на нашем домене → 302 на полный URL |
| «полная ссылка» | целевой URL + развёрнутый UTM-query |
| «клики» | переходы по короткой ссылке (счётчик редиректа) |

## 2. Ключевые проектные решения

- **Новая центральная модель `MarkedLink`**, а не переиспользование `Tag`. ТЗ требует произвольный
  URL (лендинг/канал/бот/ролик) + автор + реестр + дедуп — это другой объект. `Tag`/`Bot`/`Branch`
  остаются для бото-специфичных deep-link'ов (могут быть целевым URL метки).
- **Справочник синхронизируем в локальную таблицу** `UtmDictionaryEntry` (не читаем CSV на каждый
  рендер). Форма читает из локальной таблицы → скорость + работа при недоступности источника.
  Ложится на Phase 3 «авто-sync».
- **Сокращатель — свой, внутри проекта (решение Б=б2).** Короткий код → 302 → полный URL, инкремент
  счётчика. Универсально для всех типов ссылок. «Клики» = этот счётчик.
- **Валидация серверная**, не только на фронте: select ре-валидируется против справочника,
  маска и URL проверяются в форме. «Принуждение» должно быть неубираемым.
- **Автор «из авторизации»** — есть роль `marketer` ([models.py:483](../marks/models.py)) и
  декоратор `require_roles` ([permissions.py:8](../marks/permissions.py)).

## 3. Модель данных (новое / изменения)

### `UtmDictionaryEntry` (новая)
Справочные значения из CSV (вкладки 02 medium, 03 source, 04 campaign).
- `field` — choices: `source | medium | type | direction | funnel`
- `value` — каноническое значение (`yandex`, `cpc`, `oge`…)
- `label` / `meaning` — человекочитаемое (опц.)
- `group` — группа для аналитики (source: рекл.кабинет/CPA-сеть/…; medium: Performance/Organic/…)
- `is_template` — шаблонный source-маска (`tg-<имя>`, `<partner>`, `<teacher>`, `ig-<имя>`,
  `yt-<имя>`, `max-<имя>`, `<площадка>-<имя>`): не прямой выбор, а ввод по маске
- `is_active` — из колонки «Активно» (`google_ads`=НЕТ → скрываем)
- `synced_at`

### `MarkedLink` (новая) — реестр
- `original_url` — вставленный целевой URL
- `utm_source, utm_medium, utm_campaign, utm_term, utm_content`
- компоненты кампании: `mark_type, direction, funnel, name` (для фильтров и сборки campaign)
- `full_url` — original_url + UTM-query
- `author` (FK User), `created_at`
- `pending_review` — флаг «на заявку Грише» (шаблонный source)
- `short_link` (O2O/FK `ShortLink`, null пока не сгенерили)
- дедуп: `unique` по (`original_url` + полный набор UTM)

### `ShortLink` (новая) — сокращатель
- `code` — уникальный короткий слаг
- `target_url` — полный URL (с UTM), куда редиректим
- `clicks` (int, default 0), `last_click_at`
- `created_by` (FK User), `created_at`

## 4. Правила «принуждения» (Phase 3, серверные)

- **URL:** только `http(s)`, ASCII-host/path; кириллица/пробелы → ошибка.
- **Маска `имя/term/content`:** `^[a-z0-9-]+$` (латиница, цифры, дефис; без пробелов и `_`).
- **campaign:** `тип_направление_воронка_имя`; `_` только между частями, `-` внутри
  (`tgk-python2026`, `bot-efir`).
- **Select-поля:** значение обязано существовать в `UtmDictionaryEntry` (ре-валидация в форме).
- **Шаблонные `source`:** проверка формата маски + `pending_review=True`.
- **Дедуп:** (original_url + метка) уже есть → возвращаем существующую запись.

## 5. Сокращатель (редирект)

- Маршрут `GET /s/<code>/` → 302 на `target_url`, `clicks += 1`.
- **Домен — наш** (`automarks.tw1.ru/s/<code>` или сабдомен `go.automarks.tw1.ru`). Домен ЕГЭленда
  функционально не нужен (только брендовость); `el-ed.ru` занят лендингом → потребовал бы сабдомен +
  DNS/TLS/согласование. Инфра-блокер снят.
- База домена — из env `SHORTLINK_BASE_DOMAIN` (дефолт — наш домен). Если позже понадобится брендовый
  `l.el-ed.ru` — правка одной переменной.

## 6. Справочник CSV

Google Sheet «ЕГЭленд · Справочник UTM v.2», 9 вкладок (каждая = отдельный CSV):
`00 Регламент, 01 Поля, 02 medium🔒, 03 source🔒, 04 campaign🔒, 05 Генератор, 06 Миграция, 07 Оплата`.
Для генератора нужны **02, 03, 04**. 05 — эталон поведения (формула сборки). 01/06/07/00 — референс.

- Management-команда `sync_utm_dictionary`: читает вкладки 02/03/04 (`requests` + `csv`) → upsert в
  `UtmDictionaryEntry` → `is_active=False` для исчезнувших. Cron по образцу `scripts/sync_to_global.sh`.
- **Толерантный парсинг** (вёрстка «для людей»): пропускаем строки `ПРИМЕР`, пустые, `__`; в листе 04
  детектируем секции «Часть 1/2/3» → `type/direction/funnel`; `<...>` → `is_template=True`; читаем
  колонку «Активно» и «Группа».
- ⚠️ **Нужны CSV-URL вкладок** (публикация Google Sheet «в CSV» на вкладку) — либо разовая выгрузка
  файлов для Phase 1, авто-URL для Phase 3.

## 6a. Правила полей (уточнено по справочнику)

- `utm_term` — **обязательное** (лист 01: «нужно отделу трафика»).
- `utm_content` — только ID объявления.
- `campaign` = `тип_направление_воронка_имя` (порядок: тип, потом направление; в листе 05 «Направление»
  отдельной колонкой, но в метке идёт 2-й частью).
- Шаблонные `source` (`tg-<имя>` и т.п.): ввод по маске `<prefix>-<имя>`, `имя` ⊂ `[a-z0-9-]+`;
  ставим `pending_review=True` («на заявку Грише»).
- (Опц., Phase 3) кросс-правила: `medium=bloggers` ⇒ `source`=блогер и т.п. — мягкая подсказка.
